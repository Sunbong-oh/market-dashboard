# 공통 (모든 세션이 먼저 읽기)

## 저장소·배포
- 홈페이지: https://sunbong-oh.github.io/market-dashboard/ — 저장소 `Sunbong-oh/market-dashboard`(공개). 코드 `build_site.py`, main 에 merge 하면 `site.yml` 이 다시 만든다(몇 분, 2시간마다 예약도 있음).
- 수급·KB 쪽 저장소 `Sunbong-oh/kb-market-report`(공개): 장중 수급, 장마감 리포트, 실적 감시, 실적 보고서.
- 작업 방식: 작업 브랜치에서 커밋 → PR → squash merge. market-dashboard 작업 브랜치는 `claude/youthful-fermi-qicdat`(merge 뒤 `git fetch origin main && git reset --hard origin/main && git push --force-with-lease origin HEAD:claude/youthful-fermi-qicdat`). kb-market-report 는 매번 새 `claude/*` 브랜치.
- 커밋 메시지·PR 에 모델 이름을 넣지 않는다. `.gitignore` 는 화이트리스트(`!/이름`).
- **`trigger/`, `trigger-live/`, `trigger-site/`, `trigger-podcast/`, `trigger-consensus/` 폴더는 루틴만 건드린다**(push 하면 텔레그램 발송·실행 작업이 깨어남).
- 텔레그램은 실적 카드를 새로 만들거나 고쳤을 때, 시간외 급등락 알림, KB 접속 장애 알림만 보낸다.
- 관리자 비밀번호 `brian`(방문자 현황 `/visits/`에서 입력하면 그 기기에서 방문자 띠가 보인다). 고객 이름은 URL 조각(#)·폰에만 둔다. 종목 추가·삭제 같은 관리는 사용자만.

## 회사 PC 실행기 (KB증권 Open API)
- KB가 해외 IP 를 막아 GitHub 서버·Claude 환경에서는 KB 접속이 안 된다. **회사 PC `KVID-101007`(한국 IP)의 GitHub 실행기**에서 KB 작업을 돌린다. 자세한 건 `CLAUDE.md` '회사 PC 실행기' 절.
- PC 는 평일 08:10 켜지고 17:00 꺼진다. 실행기 창 3개(`actions-runner`=①, `actions-runner2`=②, `actions-runner3`=③, market-dashboard용 — kb-px 가 PC 에서 성공해 설치·가동 확인됨)가 각각 떠 있어야 한다. 한 실행기는 한 번에 작업 하나만 한다.
- **회사 PC 보안 장비가 HTTPS 를 가로채** 파이썬이 `CERTIFICATE_VERIFY_FAILED` 를 낸다 → `tls_trust.py` 가 윈도 인증서 저장소를 쓰게 한다(실행 파일 맨 위에서 import).
- **작업을 취소(재시작)하면 PC 에 옛 서버가 남을 수 있어** 시작할 때 8000 포트를 정리하게 해 뒀다(`live_snapshot.free_port`). 재시작은 한꺼번에 모아서 하고, 시작 뒤 첫 스냅샷이 올라오는지 확인한다.
- 실행 중인 작업의 기록은 못 읽는다(끝나야 읽힘). 로그가 필요하면 작업을 취소한 뒤 읽는다.

## 이 환경의 한계
- 이 클라우드 환경에서는 KB·나스닥 스크리너 등이 막혀 있다. 홈페이지 상태는 Playwright(`channel` 기본 chromium, `/opt/pw-browsers/chromium`)로 직접 열어 확인한다. 휴대폰 시험은 `devices['Galaxy S9+']`.
- `gh` CLI 는 읽기와 `gh workflow run` 은 되지만 `actions/runners` 같은 일부 경로는 막힌다. 작업 취소·merge·PR 은 GitHub MCP 도구를 쓴다.
